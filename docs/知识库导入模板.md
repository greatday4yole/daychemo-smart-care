# 专科知识库导入模板与操作说明

> 用途：院方提供宣教素材、处置 SOP、HFMEA 风险条目与 AI 问答口径后，按本模板整理导入系统。  
> 版本 v1.0

---

## 1. 导入内容总览

系统内置的知识资产分为五类，均可在**不改源码**的前提下通过页面维护或按本模板批量导入：

| 类别 | 系统位置 | 建议条数 | 维护页面 |
|---|---|---|---|
| ① AI 问答知识库 | `src/data/kb.ts` / 页面 | 30–80 | 知识库管理 → AI 问答知识库 |
| ② 处置 SOP 库 | `src/data/sop.ts` / 页面 | 15–30 | 知识库管理 → 处置 SOP 库 |
| ③ CTCAE 分级库 | `src/data/ctcae.ts` / 页面 | 20–40 | 知识库管理 → CTCAE 分级库 |
| ④ 宣教素材库 | `src/data/education.ts` / 页面 | 30–60 | 配置中心 → 宣教素材库 |
| ⑤ 提醒模板库 | `src/data/templates.ts` / 页面 | 15–30 | 配置中心 → 提醒模板 |

**导入顺序建议**：③ CTCAE → ② SOP → ① 问答 → ④ 宣教 → ⑤ 模板（后者依赖前者的术语与分级）。

## 2. 模板一：AI 问答知识库（KB）

### 2.1 字段定义

| 字段 | 必填 | 类型 | 约束 | 示例 |
|---|---|---|---|---|
| `id` | 是 | 字符串 | 唯一，`kb-` 前缀，院内可加科室简码 | `kb-ortho-001` |
| `question` | 是 | 字符串 | 患者口语句式，≤40 字 | `化疗后发烧了怎么办？` |
| `keywords` | 是 | 字符串数组 | 3–10 个，含口语变体与数字 | `["发热","发烧","体温","38","烧"]` |
| `answer` | 是 | 字符串 | ≤400 字；分步骤用 ①②③；急症须含明确动作 | 见 2.3 |
| `category` | 是 | 字符串 | 建议固定枚举（见 2.2） | `急症识别` |
| `boundary` | 是 | 枚举 | `education` / `triage` / `emergency` | `emergency` |
| `approvedBy` | 是 | 字符串 | 姓名（职称），多人用 `/` 分隔 | `肿瘤内科 王主任医师 / 急诊科` |
| `updatedAt` | 是 | 日期 | `YYYY-MM-DD` | `2024-12-10` |
| `hits` | 否 | 数字 | 导入时填 0，系统自动累计 | `0` |

### 2.2 分类（category）建议枚举
`急症识别`｜`消化道反应`｜`骨髓抑制`｜`居家护理`｜`饮食营养`｜`检验判读`｜`随访管理`｜`化疗中安全`｜`神经毒性`｜`生活质量`｜`医保政策`｜`安全边界`

### 2.3 边界（boundary）判定规则 —— **必须严格遵守**

| 判定 | 适用情形 | 系统行为 |
|---|---|---|
| `education` | 纯宣教、护理措施、饮食、日常观察要点 | AI 自动应答 + 语音播报 |
| `triage` | 涉及个体化判断、用药剂量、方案调整、预后、报销政策 | 应答后提示"建议转医护"，并置 `needsHuman` |
| `emergency` | 危及生命的症状（发热≥38.3、出血不止、气道/循环症状、意识改变） | 强制引导联系医护/120，并生成医护预警 |

**红线**：任何涉及化疗药剂量调整、是否停药、能否改用方案、生存期预测的问题，**必须**设为 `triage`，答案中不得给出具体剂量或方案建议。

### 2.6 导入方式
- **方式 A（推荐，少量）**：知识库管理 →「新增问答条目」逐条录入。
- **方式 B（批量）**：按 2.5 的 JSON 格式整理 → 放入 `src/data/kb.ts` 追加到数组 → 重新构建发布。
- **方式 C（接口）**：生产环境提供 `POST /api/v1/kb/import`（批量 JSON），需 `kb:write` 权限（当前演示后端未开放，按需扩展）。

## 3. 模板二：处置 SOP 库

### 3.1 字段定义

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `id` | 是 | `sop-<类型>-<级别>` | `sop-allergy-2` |
| `title` | 是 | 含级别描述 | `化疗过敏反应处置（2 级：需干预的皮疹/输液中断）` |
| `category` | 是 | 固定枚举：`过敏反应`/`骨髓抑制`/`血管通路`/`消化道`/`感染`/`全身` | `过敏反应` |
| `grade` | 是 | 0（通用）或 1–4 | `2` |
| `trigger` | 是 | CTCAE 分级描述的可执行判定 | `广泛皮疹、颜面潮红、轻度胸闷，需药物干预` |
| `steps` | 是 | 数组，每步单一动作，动词开头 | `["立即停止输注，更换输液器与生理盐水维持通路","吸氧 2～4 L/min…"]` |
| `orders` | 是 | 医嘱参考（**须注明"按医嘱"**） | `["地塞米松 5～10mg iv","生理盐水 500ml 维持通路"]` |
| `recheck` | 是 | 复评时间与达标标准 | `缓解后观察 2 小时；当日不再继续输注该药` |
| `escalate` | 是 | 升级条件（可量化） | `血压下降、喉鸣、意识改变 → 按过敏性休克处理` |
| `source` | 是 | 依据出处（指南/院内制度 + 年份） | `CSCO 过敏反应分级处置（2023）` |

### 3.2 CSV 模板

```csv
id,title,category,grade,trigger,steps,orders,recheck,escalate,source
sop-allergy-2,化疗过敏反应处置（2 级：需干预的皮疹/输液中断）,过敏反应,2,"广泛皮疹、颜面潮红、轻度胸闷，需药物干预","立即停止输注并更换输液器|吸氧 2～4L/min，监测每 5 分钟|遵医嘱地塞米松+抗组胺|通知医生评估是否更换方案|30 分钟后复评并记录 ADR","地塞米松 5～10mg iv（按医嘱）|生理盐水 500ml 维持通路","缓解后观察 2 小时","血压下降、喉鸣、意识改变 → 休克流程","CSCO 过敏反应分级处置（2023）"
```

> 多值字段用 `|` 分隔（CSV 中用双引号包裹），导入脚本会拆分。

### 3.3 撰写要点
1. **步骤可执行**：每步一个动作，避免"密切观察"这类无法考核的表述。
2. **医嘱仅作参考**：必须出现"按医嘱"，系统不代替医生开立医嘱。
3. **升级条件量化**：给出具体阈值（如 SBP <90、SpO₂ <94、意识改变）。
4. **必须写复查标准**：明确复查时间与达标值（如 "G-CSF 后 48–72h 复查 ANC 直至 >2.0"）。

## 4. 模板三：CTCAE 分级库

### 4.1 字段定义

| 字段 | 说明 |
|---|---|
| `id` | 英文短码，与 KB/SOP 引用一致（`anc`/`plt`/`fever`/`allergy`/`extrav`…） |
| `term` | 标准中文术语（建议对齐 CTCAE v5.0 中文版） |
| `category` | `骨髓抑制`/`过敏`/`皮肤`/`血管通路`/`消化道`/`全身`/`神经` |
| `grade1`–`grade5` | 各级判定标准原文；无该级填 `—` |
| `note` | 临床提示（一句话，面向护士的可操作建议） |

### 4.2 关键阈值（系统自动研判所用，**修改须同步代码**）

| 指标 | 1 级 | 2 级 | 3 级 | 4 级 |
|---|---|---|---|---|
| ANC（×10⁹/L） | <2.0–1.5 | <1.5–1.0 | <1.0–0.5 | <0.5 |
| WBC（×10⁹/L） | <4.0–3.0 | <3.0–2.0 | <2.0–1.0 | <1.0 |
| PLT（×10⁹/L） | <100–75 | <75–50 | <50–25 | <25 |
| Hb（g/L） | <110–100 | <100–80 | <80 | 危及生命 |
| 体温（℃） | 38.0–38.9 | 39.0–39.9 | ≥40.0 | 危及生命 |

> 代码位置：`src/lib/ctcae.ts` 的 `gradeByLab()`。如院方采用不同阈值（如儿童或特殊方案），请同步修改该函数与本文档。

### 4.3 CSV 模板

```csv
id,term,category,grade1,grade2,grade3,grade4,grade5,note
anc,中性粒细胞计数降低,骨髓抑制,ANC<正常值下限～1.5×10⁹/L,ANC<1.5～1.0×10⁹/L,ANC<1.0～0.5×10⁹/L,ANC<0.5×10⁹/L,,化疗后 7～14 天为低谷期；ANC<1.0 需加强防护，<0.5 或发热立即联系医护。
extrav,化疗药物外渗,血管通路,局部轻度肿胀/疼痛面积<2cm,肿胀明显需局部处理,皮肤破溃/坏死倾向,大面积坏死需外科介入,,发泡剂外渗禁止热敷，按 SOP 冷敷+拮抗剂。
```

## 5. 模板四：宣教素材库

### 5.1 字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `edu-<阶段>-<序号>`，如 `edu-post-01` |
| `title` | 是 | 患者可理解的口语标题，≤24 字 |
| `phase` | 是 | `pre`（化疗前）/`during`（化疗中）/`post`（化疗后） |
| `audience` | 是 | `all` 或风险数组 `["mid","high"]` |
| `form` | 是 | `图文`/`短视频`/`语音`/`图文+语音` |
| `body` | 是 | 正文 ≤600 字，分点用 ①②③ 或 • |
| `keyPoints` | 是 | 3–5 条要点（患者端"要点回顾"展示） |
| `audio` | 否 | 语音文件名（放 `public/audio/`）；无则用系统 TTS |
| `approvedBy` | 是 | 审核人姓名（职称） |
| `approvedAt` | 是 | `YYYY-MM-DD` |
| `version` | 是 | `v1.0`/`v1.1`，内容修订须递增 |
| `tags` | 是 | 专题标签，用于评估后个体化推送匹配 |

### 5.2 建议标签词表
`化疗前`｜`流程`｜`准备`｜`药物安全`｜`外渗`｜`过敏`｜`化疗中`｜`呼叫`｜`化疗后`｜`骨髓抑制`｜`感染预防`｜`饮食`｜`营养`｜`急症`｜`就医指征`｜`复查`｜`PICC`｜`导管维护`｜`乏力`｜`情绪`

### 5.3 CSV 模板

```csv
id,title,phase,audience,form,body,keyPoints,audio,approvedBy,approvedAt,version,tags
edu-post-01,化疗后居家 7 天：骨髓抑制低谷期防护,post,all,图文+语音,"化疗后第 7～14 天白细胞和血小板通常降到最低……① 每天测体温 1～2 次，≥38℃ 立即联系医护；② 勤洗手戴口罩；③ 饮食清淡熟食；④ 软毛牙刷防出血。","每日测体温|戴口罩勤洗手|吃熟食|软毛牙刷防出血",post-01.mp3,肿瘤内科 李护士长,2024-12-08,v1.3,"化疗后、骨髓抑制、感染预防"
```

### 5.4 撰写要点
1. **标题口语化**：避免"骨髓抑制的识别与处理"这类术语标题，改为"化疗后居家 7 天：白细胞最低时怎么防护"。
2. **正文 3 段结构**：为什么（1 句）→ 怎么做（编号步骤）→ 什么情况要就医。
3. **要点必须是动作**："每日测体温"优于"注意监测体温"。
4. **风险适配**：涉及复查频次、PICC 维护等仅对中/高危可见，填 `["mid","high"]`。

## 6. 模板五：提醒模板库

### 6.1 字段定义

| `approvedBy` | 是 | 审核人 |

### 6.2 时间轴规划表（院方可按表填写后导入）

| -2h | 化疗前 | 高致敏药物配合要点、预处理说明 | mid/high | voice |
| -0.5h | 化疗前 | 化疗目的与过敏风险告知、输液配合要点 | all | voice |
| +0.5h | 化疗中 | 输注观察要点（穿刺点/呼吸/皮肤） | all | voice |
| +1.5h | 化疗中 | 饮水、如厕、呼叫方式 | all | voice |
| +6h | 化疗后 | 回家首次提醒（休息、饮水、测体温） | all | push+voice |
| +24h | 化疗后 | 症状自查上报 | all | push+voice |
| +72h | 化疗后 | 血常规复查（中危第 4 天） | mid | push+voice+sms |
| +72h | 化疗后 | 血常规复查 + 每日监测（高危第 3 天） | high | push+voice+sms |
| +120h | 化疗后 | 低谷期预警信号识别 | all | push+voice |
| +168h | 化疗后 | 第 7 天复查 + 结果上传 | all | push+voice |
| +336h | 化疗后 | 第 14 天恢复期评估 | all | push+voice |
| +504h | 化疗后 | 下次化疗前评估预约 | all | push |

### 6.3 语音文案撰写要点
1. **一句话一个意思**，句号分隔，便于分段播报。
2. **数字口语化**：`38.3℃` → "三十八度三"；`1500ml` → "一千五到两千毫升"。
3. **祈使句**："请立即按呼叫铃" 优于 "建议按铃"。
4. **避免符号**：不出现 `①`、`≥`、`×10⁹/L` 等，语音引擎会读错。

## 7. HFMEA 风险条目导入模板

原需求提到院方提供 "HFMEA 风险条目"。系统将其作为**评估表条目**与**失效模式分析**的基线数据。

### 7.1 字段定义

| 字段 | 说明 | 示例 |
|---|---|---|
| 失效模式 | 可能出错的具体环节 | `化疗前过敏史漏项` |
| 潜在失效原因 | 为什么会发生 | `口头询问后未录入系统` |
| 潜在影响 | 后果 | `再次使用致敏药物导致 3 级过敏` |
| 严重度 S | 1–10 | `8` |
| 发生度 O | 1–10 | `6` |
| 可探测度 D | 1–10（越难发现值越高） | `7` |
| RPN | S×O×D | `336` |
| 对应系统措施 | 本系统如何防范 | `评估表必填项 + HIS 药物属性自动带入 + 高致敏强制预警` |
| 责任角色 | 落地责任人 | `责任护士 / 护士长` |
| 监测指标 | 如何验证改善 | `评估完成率 ≥98%；过敏事件 0 例` |

### 7.2 CSV 模板

```csv
失效模式,潜在失效原因,潜在影响,S,O,D,RPN,对应系统措施,责任角色,监测指标
化疗前过敏史漏项,口头询问后未录入系统,再次使用致敏药物导致 3 级过敏,8,6,7,336,"评估必填项+HIS药物属性自动带入+高危红色标记",责任护士,评估完成率≥98%
骨髓抑制延迟发现,患者未按时复查且无症状上报,ANC<0.5 未及时干预进展为 FN,9,6,8,432,"风险分层自动排复查+第7天语音提醒+症状上报CTCAE自动分级",责任护士/随访护士,延迟发现例数=0
外渗识别不及时,巡视间隔过长或患者未及时呼叫,发泡剂外渗致组织坏死,9,4,6,216,"发泡剂自动标识+每30分钟巡视打卡+床旁一键上报",责任护士,巡视打卡率≥95%
```

### 7.3 导入后校验
1. 系统会基于实际 ADR 事件自动生成 HFMEA 报表（S/O/D/RPN），可与院方基线表对比。
2. 「对应系统措施」一栏应与实际功能一一对应；若某项措施系统未实现，须作为**需求缺口**登记。
3. RPN ≥200 的条目在质控报表中标红，作为优先改进项。

## 8. 导入验收清单

| # | 检查项 | 合格标准 |
|---|---|---|
| 1 | 每条记录含审核人 | 100% 有 `approvedBy` |
| 2 | KB 边界判定 | 涉及剂量/方案/预后的问题 100% 为 `triage` |
| 3 | SOP 医嘱均标注"按医嘱" | 100% |
| 4 | SOP 含可量化的升级条件 | 100% |

| 6 | 宣教要点均为可执行动作 | 抽查 10 条，≥9 条合格 |
| 7 | 语音文案无特殊符号、数字口语化 | 抽查 10 条，≥9 条合格 |
| 8 | 提醒模板覆盖化疗前/中/后 | 三阶段均 ≥3 条 |
| 9 | 高风险条目有对应系统措施 | 100% |
| 10 | 导入后功能回归 | `npm run verify` + `npm run smoke` 全绿 |

## 9. 批量导入脚本（可选）

如院方提供 Excel/CSV，可用以下脚本转换为系统数据文件（在项目根目录运行）：

```bash
node tools/import-kb.mjs ./院方知识库.csv kb       # 生成 src/data/kb.ts 片段
node tools/import-kb.mjs ./院方SOP.csv sop
node tools/import-kb.mjs ./院方宣教.csv edu
node tools/import-kb.mjs ./院方模板.csv tpl
```

脚本会：
1. 校验必填字段与枚选取值；
2. 检查 `id` 唯一性；
3. 输出统计报告（成功/失败条数与原因）；
4. 生成待人工合并的 TypeScript 片段（不直接覆盖源文件，避免误操作）。

> 未提供该脚本时，可直接按 §2.5/§3.2/§4.3/§5.3/§6.2 的字段结构手工拷贝进对应 `src/data/*.ts` 数组。
