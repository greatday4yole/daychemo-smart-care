# 日间化疗智慧照护系统 · 运维文档

> 版本 v1.0 ｜ 适用对象：信息科、运维工程师、项目实施方

---

## 1. 系统架构

### 1.1 演示版（当前公网部署）

```
        ┌───────────────────────────────┐
        │  GitHub Pages（静态托管 HTTPS）│
        │  dist/ 单页应用（React 19 + Vite）│
        └───────────────┬───────────────┘
                        │ 数据保存在浏览器 localStorage
        ┌───────────────┴───────────────┐
        │  医护 Web 端 / 患者 H5 / 床头端  │
        └───────────────────────────────┘
```

- 纯前端，无服务器依赖；所有业务规则（风险评分、CTCAE 分级、SOP 匹配、AI 检索、质控统计）在浏览器内运行。
- 演示数据仅供功能验证，**不含任何真实患者信息**。

### 1.2 院内部署版（推荐生产形态）

```
  ┌────────────┐   HL7/FHIR   ┌──────────────────────────┐
  │    HIS     │─────────────▶│                          │
  ├────────────┤              │   应用服务（Node 20+）    │
  │    LIS     │─────────────▶│   REST API + 业务规则      │
  ├────────────┤              │   SQLite / PostgreSQL    │
  │ 监护/输液泵 │── MQTT/TLS ─▶│   （可选 Redis 缓存）      │
  ├────────────┤              └────────────┬─────────────┘
  │ 消息推送平台 │◀──── HTTP ────────────────┘
  └────────────┘                          │ HTTPS
                              ┌────────────┴─────────────┐
                              │ 医护 PC/平板 │ 患者微信 H5 │ 床头屏 │
                              └──────────────────────────┘
```

### 1.3 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 19 + TypeScript 5 + Vite 6 + Tailwind CSS 3 | 构建产物单页，无运行时外部依赖 |
| 图标 | lucide-react | 开源图标库 |
| 语音 | Web Speech API（TTS/STT） + 预生成 MP3 离线包 | 不可用时自动降级为文字 |
| 演示后端 | Node 内置 `http` + `node:sqlite` | 零第三方依赖，可选用作持久化后端 |
| 生产数据库（建议） | PostgreSQL 14+ | 替代 SQLite，支持并发与备份策略 |

## 2. 环境要求

### 2.1 客户端（浏览器）

| 端 | 推荐 | 最低 | 说明 |
|---|---|---|---|
| 医护 Web | Chrome 110+ / Edge 110+ | Chrome 90 | 建议 1440×900 及以上；平板 iPadOS 16+ Safari 可用（语音识别受限） |
| 患者 H5 | 微信内置浏览器（iOS 15+/Android 10+）、Chrome | iOS 14 / Android 9 | 语音播报依赖系统 TTS；语音识别建议 Chrome/Edge |
| 床头端 | Chromium 内核大屏一体机 | — | 建议锁定全屏、禁用休眠 |

> **重要**：语音识别（STT）使用浏览器厂商在线服务（Chrome 依赖 Google 服务）。若院内网络限制外网，语音识别将不可用，此时页面自动提示改用文字输入；**语音播报（TTS）为本地合成，不受影响**。

### 2.2 服务端（生产）

| 项 | 建议配置 |
|---|---|
| CPU / 内存 | 4 vCPU / 8 GB（支撑 200 日间床位、50 并发护士） |
| 磁盘 | 100 GB SSD（含检验数据与审计日志 6 个月留存） |
| 系统 | Linux（CentOS 7+/Ubuntu 20.04+），Node.js 20 LTS 或 22 |
| 网络 | 院内 DMZ，仅开放 443；出网策略按需放通消息平台 |

## 3. 部署方式

### 3.1 演示版：GitHub Pages（已部署）

```bash
git clone https://github.com/greatday4yole/daychemo-smart-care.git
cd daychemo-smart-care
npm ci
npm run build                # 产出 dist/
# 将 dist/ 推送到 gh-pages 分支，或使用 GitHub Actions 自动部署
```

GitHub Actions 工作流（`.github/workflows/deploy.yml`）在 `main` 分支 push 时自动构建并发布到 Pages。

**演示访问入口**：
- 首页（角色选择）：`https://greatday4yole.github.io/daychemo-smart-care/`
- 患者端直达（免登录）：`https://greatday4yole.github.io/daychemo-smart-care/#/patient`
- 床头端直达：`https://greatday4yole.github.io/daychemo-smart-care/#/bedside`

### 3.2 院内部署：静态前端 + 演示后端（单机快速验证）

```bash
npm ci && npm run build
DB_PATH=/data/daychemo.db PORT=8787 node server/index.mjs
# 访问 http://<内网IP>:8787  （同时托管 dist/ 与 /api）
```

### 3.3 院内部署：生产形态（建议）

1. **前端**：`npm run build` → 将 `dist/` 交给 Nginx 或院内静态资源服务，配置 HTTPS 与 `Cache-Control`。
2. **后端**：将 `server/index.mjs` 的 SQLite 层替换为 PostgreSQL（或接入院内数据中台），并增加：
   - OAuth2/CAS 统一认证与 JWT 签发
   - 接口鉴权（角色 + 数据范围）
   - HIS/LIS 适配器（HL7 MLLP 或 FHIR REST 客户端）
   - 消息推送适配器（院内消息平台 SDK）
3. **反向代理 Nginx 示例**：

```nginx
server {
  listen 443 ssl;
  server_name daychemo.hospital.local;
  ssl_certificate     /etc/ssl/hospital.crt;
  ssl_certificate_key /etc/ssl/hospital.key;

  add_header Strict-Transport-Security "max-age=31536000" always;
  add_header X-Content-Type-Options nosniff always;
  add_header X-Frame-Options SAMEORIGIN always;

  root /opt/daychemo/dist;
  location / { try_files $uri /index.html; }

  location /api/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

### 3.4 微信小程序 / 公众号承载患者端

患者端为响应式 H5，二选一：

- **方案 A（推荐，周期短）**：公众号菜单挂 H5 链接 + 微信网页授权获取 openid（需备案域名 + 公众号 AppID）。
- **方案 B（原生体验）**：用 `webapp-miniprogram/` 壳工程，`web-view` 指向已备案 H5 域名；小程序后台配置业务域名白名单。

> 原生小程序发布需：企业主体小程序 AppID、域名 ICP 备案、HTTPS 证书、微信审核（医疗类目需提供资质）。

## 4. 配置项

### 4.1 环境变量（后端）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8787 | 监听端口 |
| `DB_PATH` | `server/daychemo.db` | SQLite 数据库路径；生产建议放独立数据盘 |
| `CORS` | `0` | 设为 `1` 时允许跨域（仅联调用） |

### 4.2 业务配置（源码集中管理，改后重新构建）

| 文件 | 内容 | 修改影响 |
|---|---|---|
| `src/data/riskForm.ts` | 评估条目、权重、阈值、联动动作 | 调整风险分级口径 |
| `src/data/ctcae.ts` | CTCAE 分级阈值与文本 | 调整自动分级标准 |
| `src/data/sop.ts` | 处置 SOP | 更新临床路径 |
| `src/data/templates.ts` | 提醒模板（时序/话术/渠道） | 调整提醒策略 |
| `src/data/education.ts` | 宣教素材 | 更新宣教内容 |
| `src/data/kb.ts` | AI 问答知识库与边界 | 调整 AI 应答范围 |
| `src/lib/permissions.ts` | 角色权限矩阵 | 调整权限分配 |

> 上线后，模板/宣教/知识库的日常维护**无需改源码**，在「配置中心」「知识库管理」页面完成并留审计。

### 4.3 语音相关

| 项 | 说明 |
|---|---|
| 语速范围 | 0.7–1.3（推荐 1.0）；患者端三档（0.8/1.0/1.2） |
| 免打扰 | 默认 22:00–07:00，跨零点支持 |
| 离线语音包 | `public/audio/*.mp3` + `manifest.json`；重生成命令见 5.3 |
| 语音选型 | 自动挑选 `zh-CN` 声音（Tingting/Xiaoxiao/Huihui 等），无匹配则用浏览器默认中文音 |

## 5. 运维操作

### 5.1 数据备份（生产）

```bash
# SQLite 在线备份（推荐 cron 每日 02:00）
sqlite3 /data/daychemo.db ".backup '/backup/daychemo-$(date +%F).db'"

# PostgreSQL
pg_dump -Fc daychemo > /backup/daychemo-$(date +%F).dump

# 保留策略：日备 7 份、周备 4 份、月备 12 份（可用 logrotate 或 rclone 归档）
```

### 5.2 日志

| 日志 | 位置 | 内容 |
|---|---|---|
| 应用日志 | 容器/进程 stdout，建议接入 ELK | 启动、异常、接口调用 |
| 审计日志 | 表 `audit`（API `/api/v1/audit`） | 全量操作留痕（只追加） |
| 访问日志 | Nginx `access.log` | IP、UA、耗时、状态码 |

> 审计日志按等保要求留存 ≥6 个月；医疗数据操作日志建议留存 3 年。

### 5.3 离线语音包重生成

```bash
# macOS（需要 say + ffmpeg）
VOICE=Tingting SPEECH_RATE=165 node tools/gen-audio.mjs
# 输出 public/audio/*.mp3 + manifest.json；重跑构建后生效
```

Linux 环境可替换为 `espeak-ng` 或 `piper` 生成，或使用院方采购的商用 TTS 预生成。

### 5.4 版本发布与回滚

```bash
# 发布
npm ci && npm run verify && npm run build
git tag -a v1.2 -m "发布说明"
git push origin main --tags

# 回滚（前端）
git checkout <上一个 tag> && npm ci && npm run build && 替换 dist/
```

发布前检查清单：
1. `npm run verify` 全绿（业务规则）
2. `npm run smoke` 全绿（端到端，需先启动预览服务）
3. 演示数据已重置、无真实患者信息
4. 文档与变更记录已更新

### 5.5 定期巡检（建议）

| 周期 | 检查项 |
|---|---|
| 每日 | 接口连通性（HIS/LIS/消息/监护）、未闭环 ADR 积压、漏访数量 |
| 每周 | 备份可恢复性抽验、磁盘占用、审计日志完整性 |
| 每月 | 质控指标趋势（评估/宣教/随访完成率、延迟发现例数）、权限变更复核 |
| 每季 | 等保整改项、账号权限复核、SOP 与知识库版本评审 |

## 6. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 页面空白 | `dist/` 未部署或路径错误 | 检查 `base` 配置（当前为 `./`，支持子路径）；查 Nginx 日志 |
| 语音无声音 | 免打扰时段 / 浏览器不支持 / 未交互 | 检查患者端"我的"设置；换 Chrome；先点击页面任意位置 |
| 语音识别无响应 | 未授权麦克风 / 网络限制 / Safari 不支持 | 浏览器设置允许麦克风；改用文字输入；用 Chrome |
| API 500 | 数据库路径不可写 / 表结构未初始化 | 检查 `DB_PATH` 权限；首次启动会自动建表；查应用日志 |
| API 404（静态） | 路径非 `index.html` 且无匹配文件 | 正常行为（回落到 SPA）；如为接口则检查路由拼写 |
| 导出的 CSV 乱码 | 用记事本另存为 ANSI | 直接用 Excel 打开（文件已带 BOM） |
| 数据"消失" | 换浏览器/清缓存（演示版为 localStorage） | 生产版使用服务端存储，不受影响 |
| 高危预警未推送 | 消息平台鉴权失效 | 检查消息平台 token；查看 `/api/v1/audit` 最近调用 |

### 6.1 健康检查

```bash
curl -s https://<host>/api/health
# {"ok":true,"db":"daychemo.db","node":"v20.x","at":"..."}
```

### 6.2 关键接口自检

```bash
curl -s -X POST https://<host>/api/v1/integrations/lis/results \
  -H 'content-type: application/json' \
  -d '{"patientId":"p3","wbc":1.9,"anc":0.86,"plt":52,"hb":96,"orderId":"LIS-CHK-1"}'
# 预期 findings 含 anc 3 级、plt 2 级，adrs ≥ 1
```

## 7. 安全与合规

| 项 | 要求 | 当前实现 |
|---|---|---|
| 传输加密 | TLS 1.2+ | GitHub Pages 强制 HTTPS；院内建议 TLS 1.3 |
| 存储加密 | 患者标识与敏感字段加密 | 生产版建议字段级 AES-256（密钥由 KMS 托管）；演示版不存真实数据 |
| 隐私脱敏 | 列表/导出默认脱敏 | `maskName/maskPhone/maskMrn`，完整信息需高权限 |
| 访问控制 | RBAC + 数据范围 | 六角色权限矩阵；患者仅见本人数据 |
| 审计 | 全量操作留痕 ≥6 个月 | `audit` 表只追加，页面可查可导出 |
| AI 边界 | 不生成诊疗方案 | 检索式知识库 + 三级边界 + 强制免责声明 |
| 等保 | 三级要求 | 生产需按《GB/T 22239》完成定级备案与整改测评 |
| 数据出境 | 不涉及 | 演示环境无服务端存储 |

**上线前必须完成**：
1. 清空演示数据，接入院内真实数据源（HIS/LIS）。
2. 关闭"免登录角色切换"入口，接入统一身份认证。
3. 完成等保测评与医疗数据安全自查。
4. 由医务科/护理部对全部 SOP、宣教、知识库内容签字确认版本。
