> 版本 v1.1 ｜ 状态：已实现（在线演示可访问） ｜ 更新日期 2026-11-26  
> 基线来源：《日间化疗患者智慧照护系统开发需求说明书》（HJ 日间化疗项目）  
> 本文档在原需求基础上补全了**业务规则、字段口径、状态机、接口契约、验收标准**，并标注每一项需求的实现位置与验证方式。

## 一、项目概述与目标

### 1.1 建设背景
日间化疗（Day Chemotherapy）患者当日完成输注即回家，具有"住院时间短、居家风险高、随访分散、宣教不到位、骨髓抑制/过敏等不良反应识别滞后"的特点。本项目以**全流程闭环**为主线构建智慧照护平台：

```
化疗前风险评估  →  化疗中实时监控  →  化疗后居家随访
     ↓                  ↓                  ↓
 分层风险等级      巡视打卡/监护预警    AI 语音提醒/症状上报
     └────────── ADR 闭环处置（CTCAE 分级 + SOP 处置 + 追踪）──────────┘
                            ↓
                质控可追溯（HFMEA / 品管圈 / 审计）
```

### 1.2 五项目标与可度量指标

| 目标（原需求） | 落地可度量指标 | 目标值 | 系统实现 |
|---|---|---|---|
| 流程闭环 | 三端数据链路贯通（医护/患者/质控） | 三端全覆盖 | 医护 Web 端 + 患者 H5/小程序 + 质控端 |
| 智能宣教提醒 | 宣教覆盖率 / 提醒已读率 | ≥90% / ≥80% | 宣教库按阶段+风险精准推送，13 条提醒模板 |
| 风险智能预警 | 高危症状 30 分钟内医护可见 | 100% | 症状上报 → CTCAE 初判 → 即时预警 + 强制引导 |
| 不良反应闭环 | ADR 事件闭环率 / 平均闭环时长 | ≥95% / ≤24h | 上报→分级→SOP→复评→闭环 五态机 |
| 质控可追溯 | 报表可导出（HFMEA/品管圈） | 100% 可导出 | CSV/JSON 导出 + 全量审计日志 |

## 三、功能需求详述

### 模块 1：化疗前风险评估（医护端）

**1.1 标准化表单 —— 14 项、5 个维度、加权百分制**

| 维度 | 条目 | 权重 | 关联 CTCAE |
|---|---|---|---|
| 过敏与既往反应 | 药物过敏史 / 既往输注过敏 / 高致敏方案 | 6 / 10 / 8 | allergy |
| 骨髓抑制风险 | 既往 3-4 级骨髓抑制 / 高骨髓抑制方案 / 第 2 周期及以上 | 10 / 6 / 4 | anc |
| 基础疾病与器官功能 | 年龄 ≥70 或 ECOG ≥2 / 合并症 / 近期感染 | 6 / 5 / 5 | — |
| 血管条件与治疗相关 | 血管条件差或中心静脉导管 / 发泡剂或刺激性药物 | 6 / 8 | extrav |
| 营养与支持 | NRS-2002 ≥3 或体重下降 >5% / 独居或依从性差 / 既往消化道反应 ≥2 级 | 5 / 6 / 4 | nausea |

**评分规则（重要补充，原需求仅要求"自动计算等级"）**
- 归一化分值 = ⌈(勾选条目权重和 / 总权重 89) × 100⌉，取值 0–100。
- 等级阈值：`0–29` 低危 ｜ `30–59` 中危 ｜ `≥60` 高危。
- 依据：HFMEA 失效模式严重度 + ASCO/NCCN 骨髓抑制风险因素（年龄、既往骨髓抑制、方案强度、合并症）。
- 可调：阈值与权重在 `src/data/riskForm.ts` 集中配置，便于院内按本地数据校准（属"可维护性"要求）。

**1.2 风险分级联动规则**

| 等级 | 自动动作 |
|---|---|
| 低危 | 常规宣教、化疗后第 7 天血常规复查 1 次、常规随访 1 次 |
| 中危 | 每日宣教推送、第 4/7/14 天复查 3 次、居家症状每日上报、48h 电话随访 |
| 高危 | 红色标记 + 高危看板置顶、化疗中每 30 分钟巡视、第 3/5/7/10/14 天复查 5 次、每日上报 + 语音优先、24h 医护随访 |

**1.3 其他要点**
- HIS 自动带入：医嘱含 3 级高致敏药物 → 自动勾选"高致敏方案"；含发泡剂/刺激性药物 → 自动勾选对应条目；年龄 ≥70 → 自动勾选"高龄"。
- 评估结果自动存档（`archivedAt`）、同步护理记录（`syncStatus: synced|pending`）、历史可调阅。
- 内嵌 CTCAE v5.0 分级库（15 个条目），勾选条目旁 `CTCAE` 徽标可即时查阅对照标准。
- 提交前必须勾选知情同意；提交后自动生成宣教清单并推送患者端。

实现：`src/pages/nurse/Assess.tsx`、`src/data/riskForm.ts`、`submitAssessment()`。

### 模块 2：化疗中实时监控（医护端 + 床头端）

**2.1 输液信息绑定**
- 关联 HIS 医嘱号、药物名称/剂量/通路、泵速、余量、预处理方案。
- 药物属性标识：`发泡剂 → 外渗高危（红）`、`刺激性 → 中风险（黄）`、`致敏等级 ≥2 → 高致敏（红）`。

**2.2 巡视打卡**
- 标准化节点：输注开始 15 分钟 / 30 / 60 / 90 分钟 / 输注结束 30 分钟。
- 高危患者节点加密至每 30 分钟；超时节点标红并计入"超时 N 分钟"。
- 打卡记录写入时间戳，可追溯（当前演示为会话内状态，生产环境写入护理记录单）。

**2.3 不良反应快速上报**
- 床旁 6 个快捷项（皮疹/瘙痒、胸闷/气促、心慌、穿刺点肿胀、恶心呕吐、发热）+ 体温 + 分级 + 补充描述。
- 提交后按 `termId + grade` 自动匹配 SOP（`sopForTerm()`），并创建 ADR 事件进入闭环。

**2.4 监护数据接入**
- 数据源：床旁监护仪、输液泵（演示为 MQTT/HTTP 模拟）。
- 阈值告警：体温 ≥38.0℃ / HR >110 / SBP <90 / SpO₂ <94% → 弹窗 + 站内预警。
- 演示动作：`模拟采集`（随机正常/异常）、接口联调页手工推送。

**2.5 床头端 AI 语音**
- 大字模式、极简三键（播放语音 / 呼叫护士 / 语音提问）。
- 播报内容来源：提醒模板库（受审核约束）。
- 语音提问 → 知识库命中 → 语音应答；超出范围提示按呼叫铃。

实现：`src/pages/nurse/Monitor.tsx`、`src/pages/patient/Bedside.tsx`、`ingestVital()`。

### 模块 3：化疗后随访与居家照护（患者端 + 医护端）

**3.1 分时序智能提醒（13 条模板，可自主开关语音）**

| 时间点 | 阶段 | 标题 | 适用 | 渠道 |
|---|---|---|---|---|
| -24h | 化疗前 | 明日化疗准备事项 | 全部 | 推送 + 语音 |
| -2h | 化疗前 | 高致敏药物配合要点 | 中/高危 | 语音 |
| +0.5h / +1.5h | 化疗中 | 观察要点 / 呼叫方式 | 全部 | 语音 |
| +6h | 化疗后 | 回家首次居家提醒 | 全部 | 推送 + 语音 |
| +24h | 化疗后 | 症状自查 | 全部 | 推送 + 语音 |
| +72h | 化疗后 | 血常规复查（中危 / 高危差异化） | 中危 / 高危 | 推送 + 语音 + 短信 |
| +120h | 化疗后 | 低谷期骨髓抑制识别 | 全部 | 推送 + 语音 |
| +168h | 化疗后 | 第 7 天复查与随访 | 全部 | 推送 + 语音 |
| +336h | 化疗后 | 第 14 天恢复期评估 | 全部 | 推送 + 语音 |
| +504h | 化疗后 | 下次化疗前评估预约 | 全部 | 推送 |

三类提醒（原需求"短期/节点/症状"）映射：短期→+6h/+24h，节点→+72h/+168h/+336h/+504h，症状→+120h 与症状上报联动。

**3.2 AI 语音交互**
- 普通话 TTS（Web Speech API，语速 0.8/1.0/1.2 三档可调），STT 语音识别（Chrome/Edge）。
- 知识库 15 条（居家护理、饮食禁忌、不良反应初判、就医指征、检验判读、边界类）。
- 三级边界：`education`（自动应答）/ `triage`（强制转人工）/ `emergency`（强制引导 120/急诊）。
- 一键转医护：生成站内通知 + 进入"AI 转人工接诊队列"。

**3.3 居家症状自助上报**
- 10 个症状图标 + 体温 + 语音快速录入（说症状自动勾选）。
- 自动 CTCAE 初判：发热按 38.0/39.0/39.5 分 1/2/3 级；出血、气道、循环症状 → 3 级 + 高危标记。
- 高危（发热 ≥38.3℃、出血不止、胸闷气促、意识改变、外渗）→ 立即推送医护 + 语音就医引导 + 生成 ADR。
- 2 级及以上自动创建 ADR 事件并匹配 SOP。

**3.4 随访闭环台账**
- 状态：`待随访 pending` / `已完成 done` / `迟访 late`（超期 1–2 天）/ `漏访 missed`（超期 ≥2 天）。
- 漏访自动二次提醒（推送 + 语音 + 短信），医护可查看/干预/填写随访记录。
- 随访记录进入质控台账，作为"随访完成率"与 HFMEA 追溯依据。

**3.5 宣教素材库**
- 10 条素材，形式：图文 / 语音 / 图文+语音（预留短视频字段）。
- 按风险等级、化疗阶段、专题标签精准推送；每条含版本号与审核署名。

实现：`src/pages/patient/Patient.tsx`、`src/pages/nurse/Followup.tsx`、`src/data/templates.ts`、`src/data/education.ts`、`src/data/kb.ts`。

### 模块 4：AI 语音提醒子系统（全流程嵌入）

| 需求 | 实现方式 |
|---|---|
| 按化疗时间轴触发 | 以化疗日 `08:30` 为基准，`offsetHours` 正负偏移生成 `dueAt`；`buildDispatches()` 按患者风险过滤生成实例 |

| 免打扰时段 | `isInQuietHours()` 支持跨零点（22:00–07:00），期间语音静默、文字照常 |
| 提醒方式 | 小程序推送 + 语音播报（演示为站内 + 语音 + 短信标记） |

### 模块 5：不良反应闭环处置

**5.1 处置 SOP 库（11 条）**：过敏 1/2/3 级与过敏性休克、ANC 1/2/3-4 级、PLT 3 级、化疗外渗、消化道反应、导管感染、居家发热。每条含触发条件、处置步骤、医嘱参考、复查要求、升级条件、依据来源。

**5.2 状态机**

```
reported（已上报） → triaged（已分级） → handling（处置中） → rechecking（复评中） → closed（已闭环）
                                          ↘ 升级（3-4 级）↗
```

**5.3 自动预警**：LIS 抓取血常规 → ANC/PLT/WBC/Hb 按 CTCAE 阈值研判 → ≥2 级自动建 ADR 并推送责任护士；≥3 级标记高危。

**5.4 追踪闭环**：记录上报时间、每步处置措施、处置人、复评结果；闭环时写入 `closedAt`。

**5.5 导出**：ADR 追踪台账 CSV（含"延迟发现"标记），供 HFMEA/品管圈分析。

实现：`src/pages/nurse/Adr.tsx`、`src/data/sop.ts`、`reportAdr()` / `advanceAdr()` / `ingestLab()`。

### 模块 6：质控管理与数据统计

| 指标 | 口径定义 |
|---|---|
| 风险评估完成率 | 有 ≥1 条已提交评估的患者数 / 在管患者数 |
| 宣教覆盖率 | 收到 ≥1 条推送（非静音）的患者数 / 在管患者数 |
| 随访完成率 | status=done 的随访 / **已到期**随访任务数（未到期任务不计入分母，避免月末虚低） |
| 迟访数 / 漏访数 | status=late / status=missed |
| ADR 上报数量 & 3-4 级占比 | 按 term 分类统计 |
| 骨髓抑制延迟发现例数 | ANC/PLT ≥3 级事件中，首次医护动作距事件创建 >24h 或缺失（**口径已补充定义**） |
| 平均闭环时长 | closed 事件 (closedAt - createdAt) 均值（小时） |
| 提醒已读率 | 已读或已确认的分发数 / 总分发数 |

- **风险看板**：高危患者、指标异常患者、迟访/漏访患者三栏。
- **报表导出**：HFMEA（失效模式/S/O/D/RPN）、品管圈（按类型发生例数 + 3-4 级占比 + 改善建议）、质控明细表、审计日志。
- **权限分级**：见 2.2。

实现：`src/pages/qc/Qc.tsx`、`src/lib/qc.ts`。

### 4.2 院内部署时的对接约定（补充）
- **HIS**：HL7 v2.5 `ADT^A01/A08`（患者）、`ORM^O01`（化疗医嘱）；或 FHIR R4 `Patient`、`MedicationRequest`。
- **LIS**：HL7 v2.5 `ORU^R01`（血常规），或 FHIR `Observation`（LOINC：ANC 751-8、PLT 777-3、WBC 6690-2、Hb 718-7）。
- **消息平台**：HTTP REST（站内 / 短信 / 企业微信）。
- **监护设备**：MQTT over TLS，主题 `hospital/ward/{bed}/vitals`，QoS 1。
- **数据标准**：WS 445 电子病历基本数据集；等保三级；患者标识使用院内脱敏 ID，跨系统不外传姓名与手机号明文。
- **幂等与重试**：检验结果按 `orderId` 幂等；失败重试 3 次，指数退避。

## 八、与原需求的差异与补充说明

1. **补充"评分算法"**：原需求只说"自动计算风险等级"，未定义算法。本方案给出 14 项加权归一化 + 30/60 阈值，并在源码中集中可配置。
2. **补充"骨髓抑制延迟发现"口径**：原需求列为统计项但无定义，本方案定义为"ANC/PLT ≥3 级事件首次医护动作 >24h 或缺失"。
3. **补充"管理员"角色**：原需求五类角色未覆盖运维，本方案增设并对齐接口联调权限。
4. **小程序实现方式**：原需求要求"患者微信小程序"。本项目以**移动端 H5（响应式，可直接挂载微信小程序 webview 或作为公众号菜单页）**交付，并附 `webapp-miniprogram/` 壳工程说明；真正的微信原生小程序需企业 AppID 与域名备案后发布，属部署阶段外部依赖。
5. **HIS/LIS 为模拟接口**：演示环境不连接院内系统，提供同一套 REST 契约与模拟推送入口；院内对接需院方提供接口文档与测试环境。
6. **AI 不接大模型诊疗**：按原需求"AI 不可随意生成诊疗方案"，本项目 AI 采用**检索式知识库 + 规则边界**，不引入生成式模型直接输出诊疗结论，规避幻觉风险。
